How it works

1
Edge checks

CAPTCHA, size cap and rate limits applied at the edge before the request goes any further.

2
Accepted immediately

The form gets its answer first; processing continues in the background.

3
AI scoring

The lead is scored by an AI model; the email address and phone number are not sent to the model.

4
Stored once

Delivery flags prevent duplicate sends even if the pipeline retries.

5
Follow-up prepared

Email, SMS and CRM sync for warm and hot leads; cold leads are stored only.

6
Slack summary

Posted without personal details so the alert is safe to share in a team channel.

What is live and what is dry-run

Dry-run is the default; sending is enabled only by an explicit setting.

Built to fail safely

API key on every route Every API route needs a key; only the health check is open.
No direct internet access The services behind the form are not reachable from the internet directly.
CAPTCHA fails closed A missing or invalid token is rejected before the request reaches the backend.
Classified retries Failed steps are classified and retried with backoff, up to 3 attempts.
Rule-based fallback If the AI is unavailable on the final attempt a rule-based scorer still stores the lead.
First write wins A retried request cannot overwrite a stored lead; idempotency is enforced at write time.
